# 服务器操作标准化规则

本文档规定了 FY Squad MB 项目中服务器操作的管理规范，明确定义了通过 SSH 协议和腾讯云 API 接口执行操作的适用场景、安全规范和审计要求。

---

## 第一章 操作类型与访问方式分类

### 1.1 配置修改类操作

| 操作名称 | 适用访问方式 | 说明 |
|---------|-------------|------|
| 操作系统配置调整 | SSH | 包括 sysctl 参数、网络配置、系统服务配置等 |
| 应用配置文件修改 | SSH | 业务应用配置文件编辑 |
| 环境变量配置 | SSH | 系统/应用环境变量调整 |
| 防火墙规则配置 | SSH | iptables/firewalld 规则管理 |
| DNS 配置修改 | 腾讯云 API | 域名解析记录变更 |
| 安全组规则配置 | 腾讯云 API | 云服务器安全组 inbound/outbound 规则 |

### 1.2 服务启停类操作

| 操作名称 | 适用访问方式 | 说明 |
|---------|-------------|------|
| 业务服务启停 | SSH | 应用服务进程管理 |
| 系统服务管理 | SSH | systemd 服务单元管理 |
| 容器服务管理 | SSH | Docker/容器生命周期管理 |
| PM2 进程管理 | SSH | Node.js 应用进程管理 |
| 云服务器重启 | 腾讯云 API | 实例重启操作 |
| 云服务器开机/关机 | 腾讯云 API | 实例状态管理 |

### 1.3 数据备份类操作

| 操作名称 | 适用访问方式 | 说明 |
|---------|-------------|------|
| 数据库备份 | SSH | 导出数据库数据 |
| 文件备份 | SSH | 业务文件复制/打包 |
| 快照创建 | 腾讯云 API | 云硬盘快照 |
| 镜像制作 | 腾讯云 API | 自定义镜像 |
| 备份文件下载 | SSH | 远程下载备份文件到本地 |

### 1.4 资源管理类操作

| 操作名称 | 适用访问方式 | 说明 |
|---------|-------------|------|
| 云服务器创建/销毁 | 腾讯云 API | 实例生命周期管理 |
| 云硬盘挂载/卸载 | 腾讯云 API | 存储资源管理 |
| 带宽调整 | 腾讯云 API | 网络带宽修改 |
| 资源监控 | SSH + API | 混合方式：API 获取云资源，SSH 获取系统指标 |

### 1.5 日志与诊断类操作

| 操作名称 | 适用访问方式 | 说明 |
|---------|-------------|------|
| 系统日志查看 | SSH | /var/log 目录日志 |

| 云审计日志 | 腾讯云 API | API 调用历史记录 |
| 性能监控 | SSH | top/htop/vmstat 等 |
| 网络诊断 | SSH | ping/traceroute/netstat 等 |

## 第二章 SSH 操作规范

### 2.1 认证方式

- **密钥认证**: 必须使用 SSH 密钥对进行认证，禁止使用密码认证
- **密钥管理**: 私钥文件必须存放在本地安全目录，权限设置为 600
- **密钥轮换**: 建议每 90 天更换一次 SSH 密钥对

### 2.2 权限控制

- **最小权限原则**: SSH 登录账号仅授予必要的系统操作权限
- **sudo 权限**: 仅在需要时授予 sudo 权限，操作完成后及时撤销
- **禁止 root 远程登录**: 禁止通过 SSH 直接使用 root 账号登录

### 2.3 安全规范

- **连接加密**: 必须使用 SSH 2.0 协议，禁用 SSH 1.0
- **端口修改**: 建议将默认 SSH 端口 22 修改为其他端口
- **失败锁定**: 配置 SSH 登录失败锁定机制（Fail2Ban 或 iptables）
- **连接超时**: 空闲连接超时设置不超过 30 分钟

### 2.4 操作流程

1. 建立 SSH 连接前，确认目标服务器 IP 和端口
2. 使用密钥认证建立连接
3. 执行必要的操作命令
4. 记录操作日志
5. 断开 SSH 连接

## 第三章 腾讯云 API 调用规范

### 3.1 鉴权机制

- **SecretId 和 SecretKey**: 使用项目配置文件中的凭据进行身份验证
- **鉴权方式**: 腾讯云 TC3-HMAC-SHA256 签名算法
- **凭据安全**: SecretKey 严禁硬编码在代码中，必须通过安全配置获取

### 3.2 请求格式

- **请求协议**: HTTPS
- **请求方法**: GET 或 POST
- **公共参数**: 必须包含 Action、Version、Region、Timestamp、Signature 等参数
- **请求编码**: 所有请求参数必须使用 UTF-8 编码

### 3.3 错误处理

| 错误码 | 说明 | 处理方式 |
|-------|------|---------|
| AuthFailure | 鉴权失败 | 检查 SecretId/SecretKey 是否正确 |
| ResourceNotFound | 资源不存在 | 确认资源标识是否正确 |
| InvalidParameter | 参数无效 | 检查请求参数格式 |
| RequestLimitExceeded | 请求频率超限 | 降低调用频率 |
| InternalError | 内部错误 | 重试或联系腾讯云支持 |

### 3.4 调用限制

- **频率限制**: 遵守腾讯云 API QPS 限制，单实例不超过 20 QPS
- **重试机制**: API 调用失败后，间隔 3 秒重试，最多重试 3 次
- **幂等性**: 涉及资源创建的操作需支持幂等（通过 ClientToken 参数）

## 第四章 操作审计与日志记录

### 4.1 日志记录要求

#### SSH 操作日志

- **记录内容**:
  - 操作时间（精确到秒）
  - 操作者标识
  - 目标服务器 IP
  - 执行的命令
  - 命令输出摘要
  - 操作结果（成功/失败）
- **存储位置**: 本地日志目录 `./logs/ssh/`
- **日志格式**: JSON 格式，便于后续分析
- **保留周期**: 至少 90 天

#### API 调用日志

- **记录内容**:
  - 调用时间
  - API 接口名称
  - 请求参数（敏感信息脱敏）
  - 响应状态码
  - 请求 ID（RequestId）
  - 错误信息（如有）
- **存储位置**: 本地日志目录 `./logs/api/`
- **日志格式**: JSON 格式
- **保留周期**: 至少 180 天（腾讯云审计日志保留 90 天）

### 4.2 审计追踪

- **操作溯源**: 所有操作必须能够追溯到具体的执行者和执行时间
- **变更记录**: 配置文件修改必须记录变更前后的值
- **异常告警**: 操作失败或异常时触发告警通知

### 4.3 日志示例

```json
{
  "timestamp": "2026-03-12T10:30:00Z",
  "type": "ssh",
  "server": "43.138.188.183",
  "user": "Administrator",
  "command": "pm2 restart sqfy-api",
  "result": "success",
  "output": "Use --update-env to update environment variables"
}
```

```json
{
  "timestamp": "2026-03-12T10:30:00Z",
  "type": "api",
  "action": "RebootInstances",
  "requestId": "e5c6a7b8-1234-5678-9abc-def012345678",
  "params": {
    "InstanceIds": ["ins-12345678"]
  },
  "result": "success"
}
```

## 第五章 操作冲突处理机制

### 5.1 冲突类型定义

- **资源锁定冲突**: 同一服务器资源同时被 SSH 和 API 操作
- **状态不一致冲突**: SSH 和 API 对同一资源状态认知不一致
- **并发操作冲突**: 多个操作同时对同一资源进行修改

### 5.2 冲突预防机制

1. **操作队列**: 所有服务器操作进入统一队列，按顺序执行
2. **资源锁**: 对关键资源（服务器、磁盘、带宽等）实施互斥锁
3. **状态检查**: 操作执行前先检查资源当前状态

### 5.3 冲突检测流程

1. **操作前检查**: 执行操作前查询资源当前状态
2. **状态比对**: 对比本地缓存状态与实际状态
3. **冲突识别**: 发现不一致时标记为冲突状态

### 5.4 冲突处理策略

| 冲突场景 | 处理策略 |
|---------|---------|
| API 重启服务器时 SSH 正在执行命令 | 等待 SSH 操作完成后再执行 API 操作 |
| SSH 修改配置时 API 正在读取 | 锁定资源，API 操作等待或返回缓存 |
| 并发重启请求 | 第一个请求执行，后续请求跳过（幂等） |
| 状态不一致 | 强制同步本地状态与实际状态 |

### 5.5 锁机制实现

- **锁粒度**: 按服务器实例维度加锁
- **锁超时**: 锁自动释放时间 5 分钟
- **锁日志**: 记录加锁/解锁操作日志

## 第六章 实施要求

### 6.1 代码实现要求

- 所有 SSH 操作必须封装为独立的函数
- 所有 API 调用必须通过统一的 SDK 包装
- 日志记录必须作为所有操作的必要步骤
- 冲突处理必须集成到操作执行流程中

### 6.2 监控要求

- 实时监控 SSH 连接状态
- 监控 API 调用频率和错误率
- 监控操作队列积压情况

### 6.3 告警规则

- SSH 连接失败超过 3 次告警
- API 调用错误率超过 10% 告警
- 操作队列积压超过 10 条告警
- 冲突检测到资源状态不一致告警
